CI/CD SECURITY PIPELINE

Built to ship.

A demonstration of a fully automated, security-first CI/CD pipeline using GitHub Actions — from code commit to live deployment, with zero manual steps.

View on GitHub How it works ↓
PIPELINE OVERVIEW

Three stages.
Every commit.

01

Test & Lint

HTML is validated with html-validate and CSS checked on every push to catch structural issues early — before anything reaches deployment.

02

Security Scan

Trivy scans for vulnerabilities. GitHub's secret scanning and CodeQL catch exposed credentials and common code weaknesses automatically.

03

Deploy

On a successful main branch push, the site is published to GitHub Pages automatically. No manual uploads, no broken deploys.

SECURITY LAYERS

Defense in depth,
baked into the build.

🔒
Secret Scanning

GitHub's built-in secret scanning monitors every commit for accidentally exposed API keys, tokens, and credentials.

🔍
Trivy Vulnerability Scan

Aqua Security's Trivy scans the filesystem for known CVEs and misconfigurations before deployment proceeds.

⚖
CodeQL Analysis

GitHub Advanced Security's CodeQL performs static analysis to detect injection risks and logic flaws in source code.

📋
Dependency Review

Pull request checks automatically flag new dependencies with known vulnerabilities before they're merged.

👤
Branch Protection

Direct pushes to main are blocked. All changes require CI to pass, enforcing the pipeline as a gate.

🔓
Pinned Action Versions

All GitHub Actions are pinned to specific commit SHAs, preventing supply chain attacks from modified action tags.
